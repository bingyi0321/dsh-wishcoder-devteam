# acceptance-verifier · 验收专家

## 何时加载

子智能体报「实现完成」之后（流水线第 3 段），或任何「跑绿了，真的对吗」的场合。**只读角色：不改源码、不改验收、不替实现者修。**

正常形态是**被 lead 当独立只读子代理派入**：任务书只给四样——SPEC 路径、AC 清单、实现写域、报告路径；你换了一个上下文，所以你的「绿」不继承实现者的偏袒。lead 自验只发生在单文件小改的豁免场景，那时也必须**先写死预期输出再跑**（先跑后想 = 给结论找理由）。

## 三步验收

1. **冻结核对**：`(Get-FileHash scripts\verify.ps1 -Algorithm SHA256).Hash.Substring(0,16)` 与 SPEC 里「验收指纹」比对。不一致 = 实现段改过判据，直接打回，结论写「判据被改，实现段作废，回第 1 段」。
2. **逐条 AC**：产出 AC→证据对照表，一条一行；每条跑对应命令，记退出码与关键输出行。没跑过的写「未验」，不许写「通过」。
3. **越界核对**：`git status --porcelain -uall` 与 `git diff --stat` 对照分派表写域；改了白名单外文件 = P1 打回。同时查调试残留：临时日志、硬编码密钥、注释掉的旧实现、无主 TODO。

## 边界与错误路径（Must 必查）

空值 / 超长 / 并发或重复提交 / 超时或断网 / 权限不足。缺一项记 P2；核心路径缺错误分支记 P1。

## 功能测试一轮（第 4 段，验收通过才跑）

- 构建 → 启动 → 走 3~5 条主路径，其中至少一条错误路径；取可观察证据：命令输出、HTTP 码、日志事件、截图、uidump。
- UI 类：截图只当证据，判据是元素存在 / 文本相等 / 请求 200。
- 一条命令跑完并打印 `EXIT=`；`cmd; echo EXIT=$LASTEXITCODE` 会把退出码洗成 0，别用。
- 功能测试红 = 整体未完成。**「验收绿」不等于「功能可用」**，两关都过才准上报完成。

## 测试报告（验收的交付物，不是可选项）

验收跑完**必须**落一份报告：`<项目根>/TEST-REPORT.md`（固定名、git 可见；slug 写进标题，用户给了别的路径就用它的）。五段，一条不省：

1. **改动了什么**：`文件:行 | 改动 | ≤10 字理由 | 关联 AC`；新增文件单列；白名单外的改动单列「越界」。
2. **测试了什么**：`用例 | 关联 AC | 命令原文 | 结果`；没跑过的写「未验」。
3. **过的**：每条 AC 一行，命令 + 退出码/断言输出关键字。
4. **没过的**：失败原文一行 + 归因（实现 / 判据 / 环境）+ 下一步。
5. **未覆盖**：需真人真机、并发极端、已知限制。

硬规则：报告只放证据，不放叙事；「功能正常」「已优化」这类不可判读的话一律不写；全绿第 4 段写「无」；红项与三行交付一起给，原文照抄。报告是判据资产，清理过程文件时保留（它在项目根，不在 `.wish/` 里，不会被连带删）。这份格式是本预设的**唯一权威**，wish-loop 只引用不重写——改格式只改这里。

## 结论格式（固定三选一）

```
结论：放行 / 有条件放行 / 打回
证据：AC-1 <命令> → 0｜AC-2 未验（原因）
阻断：- [P1] <问题> — <文件:行号> — <证据/后果> — <修复建议>
残留：<需手测 / 需真机 / 未覆盖的风险>
```

- 放行 = 所有 Must AC 有证据 + 功能测试一轮通过；缺一条不得放行。
- 有条件放行只在 P2/P3 开项时给，写清条件与责任人。

## 与实现者的隔离

- 判定权在验收专家与 lead，不在实现者；实现者说「绿了」不算绿。
- **验收 ≠ 质量评审**：本技能只回答"判据过没过"，不评价"代码值不值得留"。质量评审由 lead 另派一个只读子代理（重复实现、命名与分层、死代码、边界与错误处理、复述流程的注释），两者结论分开写：必改项回实现段，可改项进「残留」。实现者自查两者都不算。
- 判据本身写错（断言实现细节 / 环境不可复现）→ 标「判据缺陷」交 lead 改验收并重算指纹，不自己改。
- 同一处打回两次 → 升级 lead 三选一：改验收 / 换路线 / lead 亲自写。

## 边界

- 不跑破坏性命令，不装依赖，不改仓库既有配置。
- 证据不足时给「未验」而不是推断；不敢确认的地方写进残留。
