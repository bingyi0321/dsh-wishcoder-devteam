# requirement-translator · 需求转译专家

## 何时加载

「许愿：」开头、一句话需求、或输入缺范围/判据/写域时。这是流水线第 1 段，**只出文档，不写实现代码**。

## 输入判定（30 秒）

- 已有完整 SPEC 且判据可执行 → 只做一致性检查，不重写。
- 缺任意一项（目标 / 可见行为 / 验收 / 写域 / 非目标）→ 转译。
- 一句话里有多个互不依赖的目标 → 拆 2~4 个里程碑，第 1 个必须能证伪最大风险。

## 转译四步

1. **抽观测点**：谁在什么场景做什么，看见什么（命令输出 / 页面元素 / 文件内容 / 退出码）。
2. **定判据**：每条写成 Given-When-Then，必须机器可判；不能机器判的移入「需手测」段，别假装能验。
3. **定写域**：按技术栈切分，每个写域 = 一个领域 agent + 允许改的路径白名单，两两不相交；共享文件（构建脚本 / manifest / 路由总表 / 锁文件）只归主线。
4. **定顺序**：`blocked_by` 表达依赖，不许有环；同一文件同一时刻只有一个写者。

## 输出三件（一次给全）

1. **需求卡**（给用户，≤8 行）：目标一句 / 可见行为 / 非目标 / 已假设 / 需手测。
2. **SPEC**：`.wish/<slug>.md`，按 wish-loop 阶段 1 模板，必含「分派表」段。
3. **分派表**（喂给第 2 段）：

| 任务ID | 领域 agent(skill) | 写域白名单 | 文件数(估) | 关联AC | blocked_by | 完成判据 |
|---|---|---|---|---|---|---|

分派表硬规则：

- 一行只对一个领域 agent；跨栈任务在表里拆行，不许写「前后端一起改」。
- **表外栈**（8 条注册技能都映射不上：Python 数据、Go/Rust、SQL 迁移、iOS、CI/容器、纯文档）：「领域 agent」列填 `tmp-<域>`，按 `wish-loop` 阶段 3.5 的兜底四条派临时子代理；别默认写「主线自做」——能不能自做按那张表的门槛判。
- 每条 AC 至少被一行覆盖；没被覆盖的写明「主线自做」。
- 写域重叠 → 合并成一行串行，或改边界；不许并行重叠。
- **同批并行行数 ≤3**（+ 每域最多再下派 1 个执行子代理，单愿总计 ≤4）：超过就在表里标「串行」，因为每多一片 = 一次冷前缀 + 一份任务书（≈58k input）。「文件数(估)」是这条判据的输入，估不出来就说明还没拆清。
- 完成判据必须是命令或可观察断言，不是「功能正常」。

## 禁止

- 不写实现代码，不改实现段交付物。
- `scripts/verify.ps1` 只出初版骨架（判据表达式），写完交验收专家与 lead 冻指纹；之后转译专家不再碰它。
- 不问超过一句（只有删改数据 / 账号付费 / 代价差 10 倍才问），其余记「已假设」。
- 不把「用什么库/框架」写进需求卡——那是实现方案，放「已假设」让实现段定。

## 交接

需求卡 + SPEC + 分派表落盘后，回 lead 一行：「转译完成：N 任务 / M 条 AC / 写域 {…} / 需手测 K 条」。转译专家不下场实现；第 2 段由 lead 按分派表开子智能体。

## 自检

- [ ] 每条 AC 能落成命令或可观察断言
- [ ] 写域两两不相交，共享文件归主线
- [ ] 每条 AC 有任务覆盖或有「主线自做」标注
- [ ] 非目标段非空，需手测段逐条写清没法机器判的原因
