## 何时加载
报错、崩溃、卡顿、测试挂了、线上偶现、结果与预期不符；或需查 API 用法、核实库/框架版本与能力、做技术选型、给结论要附来源。不含业务规范与页面实现。

## 一、排障流程
1. **复现**：三要素——现象（错误码/堆栈/日志）、触发条件（输入、环境、时序）、频次（必现/偶现/首现）。偶现必问"上次出现是什么时候、当时在做什么"。
2. **定界**：数据、代码、依赖、环境还是并发。查最近变更（`git log --oneline -20`、`git diff`），按"改了什么"缩范围，用二分定位可疑提交。
3. **最小用例**：缩到能稳定触发的最小片段（最小复现仓库或单测），固定环境变量、时序、随机种子。
4. **提假设**：一次只提一个可证伪假设，写清"若为真则应观察到 X"。
5. **验证**：用日志/断点/埋点/二分验证；证伪就换下一个，不叠加多改动。
6. **修根因**：只改根因，不加 try-catch 掩盖症状。
7. **补回归**：把最小用例固化成自动化测试（同目录加 `*.regression.test.*`），进 CI。

### 二分与缩圈手法
| 症状 | 首选手法 |
|---|---|
| 必现、栈清晰 | 读栈顶 3 帧 + 相关文件行号 |
| 必现、栈混乱 | 二分提交 `git bisect run <复现命令>` |
| 偶现 | 加时间戳与状态日志，抓 5~10 次样本比对，查共享状态与竞态 |
| 数据相关 | 对比正常与异常样本的最小差异字段 |
| 依赖相关 | 查版本与锁文件，升降一档做对照实验 |
| 环境相关 | 对比变量、镜像、网络、时区、locale |
| 性能相关 | 先测量定位热点（profiler/火焰图/慢查询）再改 |

### 插桩纪律
- 临时日志标 `// DEBUG:`，提交前删干净；日志带时间戳、模块前缀、关键 ID。
- 默认 INFO，DEBUG 走开关可运行时切换，不刷屏；打印用结构化字段而非大对象 `toString()`（可能含敏感信息）。
- 埋点位置：入口参数、关键分支、状态变更前后、外部调用前后（耗时 + 结果码）；性能敏感路径避免逐帧分配。

### 各栈定位速查
- **Web 前端**：Console 第一个 error 通常即根因；Network 看失败与重复请求；React DevTools 看 props/state 与多余重渲染；压缩栈用 source map 定位。
- **Node/后端**：查 unhandledRejection；`--inspect`/`async_hooks`；日志按 traceId 串联；DB 问题先看慢查询日志与连接池水位。
- **Python**：`python -X faulthandler`；`pdb`/`breakpoint()`；`py-spy top` 看死循环；虚拟环境与锁文件不一致是常见坑。
- **Java/Android**：`adb logcat`；堆栈用 `~` 换行还原；OOM 看 `dumpsys meminfo`；ANR 看 traces.txt。
- **并发/分布式**：先确认是不是时序问题——加消息 ID 与单调时钟日志；查双重检查、锁顺序、隔离级别、重试风暴。
- **CI/构建**：看第一条失败与第一条 warning；比对本地与 CI 的变量、SDK 版本、锁文件、时区。

### 常见错误模式
- 改完没生效：构建缓存/产物未更新 → 强制清缓存重编；改错文件或模块。
- 环境差异：本地正常 CI 挂 → 锁文件、时区/locale、字符集、路径大小写。
- 隐式依赖：全局变量/单例状态/测试互相污染 → 测试独立与顺序随机化。
- 数据形态假设错：字段可能 null/空/超长/Unicode/跨天 → 显式校验与边界用例。
- 并发与资源：连接池耗尽、句柄泄漏、锁顺序不一致 → 指标与最小并发复现。
- 版本错配：文档对不上实际安装版本 → 以 lockfile 与 `npm ls`/`pip show` 为准。

### 修复与止损
止损优先：灰度、回滚、feature flag 关闭、限流、降级。修复优先级：P0 止血（回滚/开关）→ P1 根因修复 + 回归测试 → P2 架构改进。提交信息写清现象、根因、改法、影响面、验证方式。

## 三、检索与核实
### 检索顺序（网络是最后手段）
1. **本地优先**：代码、注释、锁文件、CHANGELOG、堆栈里的文件名行号、vendor 源码、已落地的依赖源码（`node_modules/`、`site-packages/`、Gradle/Maven 缓存）。
2. **项目内检索**：`rg -n "关键词" .`、`rg -n "funcName\(" --type py`；先定位符号再读实现，不靠猜。
3. **本地环境**：`npm ls` / `pip show` / `go version -m` / Gradle 依赖树、`--help`、`man`、安装包内文档，以及直接跑最小脚本实测。本地能跑出结果的，不信任何文档。
4. **网络（本预设 `tool-web` 为 `disabled`，检索整体禁用）**：挡住它的不是"网没用"，是**凭证**——v22 实测 10 次 `web_search` 有 5 次失败，因为没有 `DEEPSEEK_API_KEY`。所以顺序是：1–3 查不到先按「无法核实」写进结论并标注（不许拿旧资料或臆造顶替）；真要恢复检索就去 `credentials` 配 key、删 `cordis.patch.yml` 里 `tool-web` 的 `disabled` 行，并补回 `fetch: false` 与 `searchMaxResults: 3`（每请求约 +90 tok）。
5. **无网时的替代查证**（比"我不知道"值钱）：`node_modules/<pkg>/README.md` 与 `*.d.ts`、`site-packages/<pkg>/`、Gradle/Maven 缓存里的 `-sources.jar`、`<tool> --version` 实测、包内 `CHANGELOG.md`。依赖自带的类型定义就是最权威的"文档"，且 0 请求成本。确需某页细节才定向取一次：`powershell.exe -NoProfile -Command "Invoke-WebRequest -Uri URL -UseBasicParsing | Select-String 关键行"`，只带命中行回来，网页全文不进上下文。社区帖只作线索，须被上游源码或实验确认。

### 检索式与技巧
- 取外网前先在本地 grep 一遍关键词，避免取已有答案。
- 精确报错全文加引号搜索；去掉错误码只搜关键短语；组合 `库名 + 版本 + 错误信息`。
- 结果按日期倒序看，只留 3 个月内；引用时标注发布日期。
- 读源码定位：`rg -n "函数名" 依赖目录` → 读调用点 → 看参数校验与默认值。

### 可信度分级
| 级别 | 依据 | 使用方式 |
|---|---|---|
| A | 官方文档/源码/changelog，版本与本地一致 | 直接作为依据，引用链接 |
| B | 官方文档但版本不同 | 标注版本差异，本地实测后使用 |
| C | 社区问答/博客 | 仅作线索，需官方文档或实验确认 |
| D | 无来源的二手结论 | 不采纳，标"待验证"并设计实验 |

### 核实三条硬规则
1. **版本核实**：任何"这个 API/参数/行为"的说法，先确认本地实际版本（`npm ls`、`pip show`、`go version -m`、gradle 依赖树），文档版本对不上就实测。
2. **事实 vs 推测**：明确区分"已验证（附命令输出/文件:行号）"与"推测（附验证计划）"；不确定就写不确定，不编造 API 名、参数名、链接。
3. **最小实验**：关键结论用最小脚本/单测/命令实际跑通再采信；跑不通就如实说明。

### 引用纪律
- 引用给来源名 + 版本 + 链接 + 关键段落位置；链接到具体页面（官方文档优先于搜索结果页），无法访问时说明并降级为实验依据。
- 结论后附证据：命令与输出、文件:行号、commit hash；来源冲突时写明冲突点、版本差异与采信理由。

## 四、输出格式
```text
结论：<一句话>
根因：<机制说明，定位到文件:行号 或 具体条件>
证据：<命令+输出 / 引用来源+版本+链接>
复现：<步骤或用例名>
修复：<改动点 + 影响面>
验证：<已跑的测试与结果>
待确认：<未验证项与验证计划>
```
