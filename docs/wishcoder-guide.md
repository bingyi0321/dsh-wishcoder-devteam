# 许愿式编程 · 使用说明

> 适用版本：`dsh-wishcoder-devteam` 0.0.202（预设 `devteam`，技能 `wish-loop` + `verify-harness`）
> 一句话：**你说要什么，它自己定默认值、自己写会失败的验收、自己循环到全绿，最后只报三行。**

---

## 0. 三十秒上手

在新会话里，把需求写成一句话，前面加「许愿：」：

```
许愿：做个能把手机截图批量裁成 1080x1920 并加圆角的小工具，双击能跑。
```

然后不用管它。它会把这句话变成：

1. `.wish/<slug>.md` —— 一页 SPEC（目标、可见行为、可执行验收、不可变量、已假设、非目标）；
2. `scripts/verify.ps1` —— 一条命令、退出码 0 才算过，先跑一次确认它是**红**的；
3. 实现 → 反复跑验收 → 全绿；
4. 三行收尾：

```
改动：src/crop.js:1 新增批量裁图 ｜清理：删 2 留 2（verify.ps1、SPEC）
验证：powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts\verify.ps1 → OK
残留：HEIC 格式未测，需真机确认
```

不满意就补一句（「圆角要 24px」），它把这条**加进验收**再跑一遍。验收是唯一口径，不靠自我感觉。

---

## 1. 它解决什么问题

普通对话式编程的失败模式很固定：说「做完了」，用户一试不对；改了三轮还在猜；跑绿了但跑的是假检查。

许愿式编程把这件事换成工程契约：

| 普通模式 | 许愿模式 |
|---|---|
| 「我将要实现……」先说后做 | 计划超过 3 行就落盘成 SPEC，回复只留一句「按计划执行」 |
| 靠自我感觉判断完成 | 只认命令退出码与断言输出，**没跑过的不许写「已验证」** |
| 跑不绿就改测试 | 验收指纹锁定，实现段改过验收 = 本段作废，回段 1 重写 |
| 反复换写法试 5 次 | 三振法则：同点失败 3 次必须换假设，6 次交回主会话裁决 |
| 交付后仓库一堆临时文件 | 阶段 5.5 清点 → 逐条删 → 删完重跑验收 |

代价也要说清楚：**它比「顺手改一行」慢**。单点小改（改文案、修一行判空）不要许愿，直接用日常模式。

## 2. 怎么触发

### 2.1 三种触发方式

| 你说的话 | 进哪个模式 |
|---|---|
| 「许愿：……」 | 许愿闭环（`wish-loop`），最稳，推荐 |
| 「做个… / 从零 / 整页 / 整功能 / 端到端…」 | persona 路由行自动进许愿 |
| 「改一下 / 修一下 / 加个字段 / 怎么报错了」 | 日常改代码（最小 diff），**不进**许愿 |
| 「这个文件重构一下」 | `devteam-flow`（跨文件编排），不是许愿 |

**拿不准就自己加「许愿：」**——少一次猜。

### 2.2 老会话里也能许愿

许愿不是预设，是 persona 的一行路由，不用新开会话。区别：这时它得先记**基线**（当前哪些验收已经是绿的，写进 SPEC），否则「先写验收、确认它红」会一开跑就是绿的——那是假绿。

### 2.3 三种值得许愿的场面

- 一句话描述一个功能/页面/脚本，你没给实现细节；
- 一次改动跨 3 个以上文件，或跨技术栈；
- 上一轮返工过：它说做完了，你说不对。

## 3. 它会怎么跑（三段分工）

一句话愿望拆三段，**段与段之间只靠文件交接**（子代理看不到本会话，也看不到你怎么想的）：

| 段 | 谁做 | 产出 | 交接物 |
|---|---|---|---|
| **1 判愿 / SPEC / 验收** | 本会话 | 一句人话目标、可执行验收、会失败的 `verify.ps1` | `.wish/<slug>.md`（含验收指纹） |
| **2 实现** | 子代理（默认）或本会话自写 | 代码，逐条把验收跑绿 | 三行回报 + 每次 verify 的关键行 |
| **3 三振不绿** | 本会话 | 改验收 / 换路线 / 亲自写关键 20% | 结论写回 SPEC 的「已知失败」段 |

四条铁律：

1. **段 1 不许派子代理**——判愿是判断题，子代理看不到全貌，也没有改 SPEC 的权限。
2. **段 2 不许改验收**——实现者只读 `verify.ps1` 与 SPEC；改验收去迎合实现，就是自己给自己出题。
3. **段 3 不许让子代理继续试**——同点失败 3 次，卡住的是设计不是手气。
4. **一次规划、多次实现**——每次开新上下文都是一次冷前缀重付（本机基线 ≈58,828 input/步）。

### 3.1 内部阶段（你不需要干预，但知道它在哪一步有用）

```
阶段 0 判愿（30 秒，不写码）→ 阶段 1 SPEC（8~20 行）→ 阶段 2 验收先行（确认红）
→ 阶段 3 最小实现 → 阶段 4 循环（跑 verify → 只读第一处失败 → 改一处 → 重跑）
→ 阶段 3.5 扇出编码（可选，写域不重叠才并行）
→ 阶段 4.6 三振接管 → 阶段 5 交付（三行）→ 阶段 5.5 清理 → 阶段 6 沉淀
```

两个关键判断点：

- **什么算做到了**：阶段 0 抽出「谁在什么场景用、什么可观察结果算做到、验收能否机器判定」。抽不出来就先做阶段 2，把判据变成可执行的。
- **什么时候问用户**：只有三个红线开关——会删除/覆盖用户已有数据；需要账号、密钥、付费、外部审批；两种做法代价差 10 倍以上且不可兼得。其余一律自己拍，写进 SPEC 的「已假设」。

## 4. 你会看到哪些文件

| 文件 | 是什么 | 交付后 |
|---|---|---|
| `.wish/<slug>.md` | SPEC：目标、可见行为、验收、不可变量、已假设、非目标、验收指纹 | 默认随交付删除（用户没要求留档时）；也可留着当复跑依据 |
| `scripts/verify.ps1` | 唯一判据。一条命令 + 退出码 + 最后一行 `OK` | **留**，三行的「验证」要引用它 |
| `%TEMP%\wish-verify\<工程名>.log` | 验收日志（仓库外，天然不进 git） | 不用清 |
| `.wish/verify.log` | 沙箱只允许写工作区时的日志回落位置 | 随 `.wish/` 一起清 |

SPEC 模板（实际生成内容更多，含指纹与基线段）：

```markdown
# WISH: <一句话>

目标：<用户能看见的结果，一句话>

可见行为：
- 打开/运行 X，做 Y，应看到 Z
- 失败时看到 <错误提示/退出码>

验收（可执行）：
- `powershell.exe -NoProfile -ExecutionPolicy Bypass -File scripts\verify.ps1` → 退出码 0，最后一行 OK
- `<单测命令>` → 0 failed

实现者：<本会话自己 / subagent:<name>>　段位：<1 判愿｜2 实现｜3 接管>
验收指纹：<sha256 前 16 位>（实现段只读；交付前父侧重算核对）

不可变量：技术栈 / 目录结构 / 现有公开 API 形状 / 不许动的文件
已假设：<自己拍的决定，逐条>
非目标：<明确不做的事>
```

**SPEC 是抗压缩的锚**：长会话里那条「许愿：…」的用户消息可能被折叠成摘要，之后每轮一律以 SPEC 文件为准，不以对话记忆为准。

## 5. 许愿怎么写（最省返工）

### 5.1 四行模板

```
许愿：<一句话说清要做什么>
验收：<怎么算做对了，能给命令最好>
不许动：<目录 / 接口 / 依赖>
预算：<几轮内、别超多少改动>
```

只有第一行是必需的，后三行是给自己买保险。

### 5.2 好愿望 vs 坏愿望

| 坏 | 为什么 | 好 |
|---|---|---|
| 「做个好用的图片工具」 | 「好用」不可判定 | 「批量把 PNG 裁成 1080×1920、圆角 24px、输出到 `out/`、双击 `.bat` 能跑」 |
| 「优化一下性能」 | 没有观测点 | 「列表 1000 行时首屏 < 500ms，用 `scripts/bench.mjs` 打印耗时」 |
| 「修一下登录」 | 没说失败现象 | 「输入错误密码时提示消失而不是红字，复现：打开 `/login` 输 `a@b.c` / `123`」 |
| 「顺便把代码整理一下」 | 范围蔓延 | 写进「非目标」，或单独一次任务 |

三条经验：

1. **给可观察的结果**，不要给实现方案（方案让它定，写进「已假设」）。
2. **能给命令就给命令**——哪怕只是「跑 `npm test` 0 failed」。
3. **明确说不做什么**，比说做什么更能防跑偏。

## 6. 三个完整例子

### 例 1 · 一次性脚本（无测试框架）

```
许愿：写个 Node 脚本，把 ./raw 下所有 .md 的标题层级统一成 ## 开头、去掉行尾空格，输出到 ./clean。
验收：node scripts/check.mjs 打印 OK；任一行有行尾空格就 exit 1。
不许动：raw/ 里的原文件。
```

它会做：SPEC → `scripts/check.mjs`（输入→输出断言）→ 确认红 → 实现 → 绿 → 清掉临时件。

### 例 2 · 前端页面（UI 类判据）

```
许愿：给现有列表页加「按状态筛选」的下拉，选完立刻刷新列表，URL 带 ?status=done。
验收：playwright 跑 scripts/e2e.mjs：点下拉选 done → 列表只剩 3 条 → URL 含 status=done；截图存 evidence/。
不许动：src/api/ 下的请求封装。
```

UI 类的规矩：**截图只当证据，不当判据**。判据是「元素存在 / 文本等于 / 请求 200」。

### 例 3 · 已有工程里加功能（要记基线）

```
许愿：给设置页加「导出配置」按钮，导出 JSON 到下载目录。
验收：现有 scripts/verify.ps1 全绿，且新增一条断言：点击后 window.__lastExport 非空。
不许动：设置项的存储 key。
```

已有工程的关键：先跑一次现有验收记**基线**，否则新验收一开跑就是绿的，分不清「我改出来的」和「本来就绿的」。

## 7. 交付物长什么样

固定三行，多一个字都不写：

```
改动：<文件:行> — <≤10 字理由> ｜清理：删 N 留 M（<留下的判据资产>）
验证：<命令> → <结果一行>
残留：<没验到的 / 需真人真机的 / 已知限制>
```

规矩：

- 没跑过的检查，不许写「已验证」；
- 许愿产出是**独立文件**（文档/视频/图片/表格/报告）→ 用 `present` 交付，附路径与一句话说明；纯代码改动留工作区；
- 清理列只在**真删过东西**时写；一个都没删就省掉。

## 8. 不满意怎么改

| 你的反馈 | 它该做什么 |
|---|---|
| 「圆角要 24px」 | 把这条加进验收 → 重跑（会先红后绿） |
| 「不是这个意思，我要的是……」 | 回段 1 重写 SPEC 的目标段，旧实现标废弃，不叠补丁 |
| 「这检查不对，应该判 X」 | 父改验收 + 重算指纹 + **重跑确认还会红** |
| 「先别做了」 | 停手，交「已绿 / 红项 / 下一步」，不留半成品实现 |

**不要**自己动手改 `verify.ps1` 让它变绿——那样后续所有「绿」都失去意义。

## 9. 常见退化（用户侧对策）

| 症状 | 它出了什么问题 | 你怎么说 |
|---|---|---|
| 回了一大段「我将要实现…」然后没动 | 先说后做 | 「先落 SPEC，再动手」 |
| 代码写完就说完成 | 假绿 | 「跑一次 verify，把最后一行贴出来」 |
| 顺手重构了三个文件 | 范围蔓延 | 「只改这条，其他回退」 |
| 每个小选择都来问你 | 过度提问 | 「你定，记进已假设」 |
| 单文件小改也开了子代理 | 为并行而派 | 「这个自己做，别派」 |
| 交付后仓库多了 `verify.log`、`*.bak`、截图 | 现场不干净 | 「按阶段 5.5 清一遍」 |
| 跑绿了但结论不对 | 实现段改过验收 | 「重算验收指纹，对不上就回段 1」 |

## 10. 成本与预算

- 一个「步」≈ 22 秒 + 58,828 input token（本机基线）。
- 预算线：**>40 步或 >15 min 未见绿就该停手交状态**，不原地续命。
- 派子代理不是省钱：实测同一任务，派发 ≈$0.0100 / 8 请求，自写 ≈$0.0039 / 4 步。派发买到的是**判据解释权被隔离** + 一条干净上下文，不是更便宜的 token。
- 什么时候不派（两种，别混用）：
  - **判据 ≥ 实现**：一次能过的活，派发固定成本（冷前缀 + 交接 + 重读任务书）纯亏；
  - **预算例外**：实现 <30 行、一次 `edit` 能完，冷前缀明显贵过自做。
- 什么时候必须派：实现跨 ≥3 个写域，或预计 ≥2 轮试错——试错是子代理唯一不可替代的产出。
- 想让实现段便宜，只能**换整场会话路由**（profile 的 `agent-default-model`），不能在 spawn 时点菜。

### 10.1 跨模型派发（可选）

会话里若有 `subagent/model-selection-policy`，可以在派发时显式传 `provider` + `model`（两个必须一起传），白名单默认两条：`deepseek-v4-pro`、`deepseek-v4.1-flash`。没有该 policy 时，显式选择只允许等于父路由，传别的会报 `child LLM route ... is not allowed for this Session`。

白名单的**顺序就是分派优先级**：排第一的是首选，分派失败（被运行时拒绝或服务不可达）自动顺延到下一条，列表用尽才回落到继承主路由。顺序在设置页用「上移 / 下移」调整。

白名单由官方插件 `subagent-model-selection-settings` 在 **profile 层**写入，页面入口：**设置 → 子代理白名单**（或 Plugins → `dsh-devteam-settings`）。`cordis.patch.yml` 里那份只是出厂默认值，改它不生效。

## 11. 排障

| 现象 | 原因 | 处理 |
|---|---|---|
| 许愿模式没被触发 | 没加「许愿：」，描述里也没有「整页/整功能/从零」 | 自己加前缀 |
| `verify.ps1` 报 `Pattern is null` / 中文乱码 | `.ps1` 无 BOM 的 UTF-8，PS 5.1 按 GBK 解码 | 脚本保持纯 ASCII（中文写成 `\uXXXX` 正则）；或补 BOM；本机没有 `pwsh` |
| `禁止运行脚本` / `running scripts is disabled` | ExecutionPolicy 全部 Undefined | 固定用 `powershell.exe -NoProfile -ExecutionPolicy Bypass -File` |
| 命令找不到 `pwsh` | 本机只有 `powershell.exe` 5.1 | 一律写 `powershell.exe` |
| 验收一开跑就是绿的 | 没记基线 / 判据写成了实现细节 | 回段 1：加基线段，判据改成可观察行为 |
| 红得很奇怪，报 `CommandNotFoundException` | 脚本自身坏了，不是功能没做 | 先修脚本（路径、引号、BOM） |
| 子代理派成别的模型被拒 | 会话没有 policy，或路由不在白名单 | 不传 `provider`/`model`；或改设置页白名单后新开会话 |
| 跑绿了但结论不对 | 实现段改过 `verify.ps1` | `(Get-FileHash scripts\verify.ps1 -Algorithm SHA256).Hash.Substring(0,16)` 与 SPEC 比对 |
| 技能不出现 / 预设列表没有 DevTeam | `customSkillDirs` 指错，或预设组装报错 | 改 §3.2 那一处 → `node validate.cjs` → 重启 |

## 12. 什么时候别用许愿

- 单点小改：改文案、修一行判空、换个颜色——日常模式更快。
- 判据只能靠人：声音、振动、人脸、真实网络。可以许愿，但这些必须写进「残留：需手测」，不许假装验过。
- 需求本身还没成形（你自己都不知道要什么）：先把需求聊清楚，再许愿。判愿阶段问不出方向的，实现阶段只会更贵。
- 会删除/覆盖你已有数据的操作：它会先问一句，别嫌烦。

## 13. 文件与版本

```
dsh-wishcoder-devteam/
├─ cordis.patch.yml   # 唯一入口：一个 preset 行（devteam, order 20, 18 插件行）
├─ roles.json         # 开发角色注册表（6 个 active）
├─ skills/
│  ├─ wish-loop/      # 许愿闭环：三段分工、阶段 0~6、反模式、自检
│  ├─ verify-harness/ # 判据分级、脚本骨架、退出码陷阱、指纹核对
│  └─ (6 个开发角色技能)
├─ validate.cjs       # 门禁：node validate.cjs
└─ docs/wishcoder-guide.md  # 本文
```

- 许愿细则在技能正文里（不进前缀缓存，随改随生效）；persona 只留触发词与覆盖规则。
- 改完 `cordis.patch.yml` 必须跑 `node validate.cjs`；宿主装载以**重启**为准。
- 详细设计取舍见 `README.md`，逐版改动与实测数据见 `CHANGELOG.md`。
